# Електронний деканат (Electronic Dean's Office)

* **Студент:** Параваєнко Володимир Сергійович

* **Група:** КН-3x

* **Короткий опис:** Бекенд-додаток для управління навчальним процесом деканату, побудований на базі FastAPI, SQLite/SQLAlchemy, із повною контейнеризацією через Docker Compose, підтримкою JWT (Access/Refresh), рольовою системою контролю доступу (RBAC) та чотирма незалежними шарами захисту (Defense in Depth).

## Інструкція запуску

Виконайте наступні команди в терміналі для запуску проєкту з чистого клону:

```
git clone https://github.com/Zentara13/information-security-practice.git
cd information-security-practice
cp .env.example .env
docker compose up -d --build
docker compose exec api alembic upgrade head
docker compose exec api python -m app.seed

```

## STRIDE-аналіз загроз та контрзаходи

| Загроза (STRIDE) | Контрзахід у вашому коді | Що можна покращити | 
| ----- | ----- | ----- | 
| **S**poofing (Підробка особи) | Криптографічно підписані JWT-токени зі строгим терміном дії та перевіркою секретного ключа. | Перехід на асиметричний підпис **RS256** із публічним/приватним ключами. | 
| **T**ampering (Модифікація даних) | Валідація та санітизація вхідних даних через Pydantic, санітизація HTML-контенту бібліотекою `bleach`. | Використання зовнішнього **WAF** на рівні мережі для фільтрації складних атак. | 
| **R**epudiation (Відмова від дій) | Базове логування подій безпеки та автентифікації на рівні сервера. | Підключення централізованої системи аудиту та збору логів (ELK / Loki). | 
| **I**nformation Disclosure (Витік даних) | Хешування паролів алгоритмом **Bcrypt** ($2b$12\$) та виключення чутливих полів із відповідей API. | Зберігання секретів у спеціалізованих сховищах (HashiCorp Vault). | 
| **D**enial of Service (Відмова в обслуговуванні) | Лімітування кількості запитів (Rate Limiting через `slowapi`) для захисту ендпоінтів. | Використання розподіленого кешу **Redis** для лімітування та захисту від DDoS. | 
| **E**levation of Privilege (Підвищення прав) | Реалізація рольової моделі доступу **RBAC** (`require_role`) на основі ролей у JWT. | Використання **HttpOnly cookie** для токенів із додатковим захистом проти CSRF. |
